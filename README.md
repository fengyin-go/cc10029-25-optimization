# 智能爬虫采集平台

面向网页爬取、API接入、增量抓取、反爬对抗与采集质量校验的数据采集平台。

这是一个前后端分离的管理平台：前端 Vue 3 + Vite + TypeScript，后端 FastAPI（Python）。
两边各自独立启动，前端 dev server 已关掉自动打开页面，启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/              统一请求封装
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false）
├── backend/                  FastAPI（Python） 后端
│   ├── app/routers/          每个业务模块一组接口
│   ├── app/services/         业务规则与状态流转
│   └── app/store.py          内存数据仓库与示例数据
├── .gitignore
└── docker-compose.yml
```

## 启动

### 后端

```bash
cd backend
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
./run.sh
```

健康检查：`curl http://127.0.0.1:8000/api/health`

### 前端

```bash
cd frontend
npm ci
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，
需要自己访问。`/api` 由 vite 代理到后端 `http://127.0.0.1:8000`。

## 约定

- 每个模块的前端页面在 `frontend/src/views/<模块>/index.vue`，后端接口在
  `backend/app/routers/<模块>.py`，业务规则在 `backend/app/services/<模块>.py`。
- 列表接口统一返回 `{ items, total, page, size }`，动作接口统一返回 `{ ok, message }`。
- 状态流转只允许在 `app/services` 里改，路由层不做业务判断。

## 代理降级决策数据流

全部代理节点检测失败时，代理池不再让采集请求反复选择失效节点，而是按既有数据流
生成**代理降级决策数据集**，处理步骤如下：

1. **提交检测**：`POST /api/proxy/degradation` 提交检测批次（节点结论：存活/失效/未检测），
   读取空池（无已启用节点）与检测失败（已启用节点全部失效）。
2. **生成决策**：记录空池原因、最近检测批次与检测时点；存在已完成检测且存活的节点时
   指定替代区域，否则任务进入可控等待。未完成检测的节点不会被当成可用替代。
3. **同事务落库**：决策数据集与爬虫引擎代理分配记录台账（`GET /api/crawler/allocations`）
   在同一事务提交，校验结论同步到台账；任一环失败整体回退，台账读不到半份数据。
4. **幂等与冲突**：重复送交（同幂等键）只写入一份，后续请求读取已存在结果；
   全池失效与局部恢复同时到达时按最新检测时点收敛，下游只得到一条生效决策。
5. **恢复与重放**：空池恢复后只允许从等待任务继续分配（等待中 → 已恢复）；
   已失败的请求不能无提示地重放，`请求重放` 必须携带重放说明；
   恢复条件不满足时说明中断原因。数据集为空时代理池页面显示空态「暂无数据可重试」。
6. **血缘**：决策可沿用冻结版（只看本批结论）或采用最新版（看节点累计状态），
   代理池会得到不同血缘结果；台账记录检测时点供操作者核对是否用了过期检测节点。
